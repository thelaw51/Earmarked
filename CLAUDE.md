# PodcastBookRecs

Self-hosted tracker for books mentioned on podcasts. .NET 10, Blazor Server with MudBlazor, EF Core on SQLite. A Worker and a UI ship as one Docker image and share `/data`. See [README.md](README.md) for the pipeline, deployment and configuration.

This repo is **public**. Never commit hostnames, IP addresses, email addresses, real feed URLs, real transcripts or a real `config.json`. Use placeholders.

```bash
dotnet test                                    # build and run all tests (xUnit v3 on Microsoft.Testing.Platform)
dotnet run --project src/PodcastBookRecs.Worker
dotnet run --project src/PodcastBookRecs.Web   # http://localhost:5237
```

Local runs read `.local/config/config.json` and write `.local/data/` (both git-ignored), set by each project's `launchSettings.json`.

## Status and roadmap

| Phase | Scope | State |
|---|---|---|
| 1 | Feed polling, published `<podcast:transcript>` fetch and parse, podcast/episode/status UI, CI/CD to GHCR | Done and deployed |
| 2 | Speech-to-text for episodes without a published transcript (whisper.cpp on a Mac, `mac/`), chunked and resumable | Done and deployed |
| 3 | Book extraction with a local LLM and quote validation, Open Library matching, ranked book list | Done |
| 4 | Review queue, book list filters and transcript links, CSV, Goodreads and JSON export | Done (`ReviewBacklog.LowConfidence`, 0.6, not yet checked against real data) |

Transcription runs natively (not in Docker) on an Apple Silicon Mac on the LAN, behind an OpenAI-compatible `/v1/audio/transcriptions` endpoint; `mac/setup.sh` installs it. Book extraction uses LM Studio on the same Mac (OpenAI-compatible `/v1/chat/completions`, Qwen3 8B), running alongside transcription. Every external backend follows the same pattern: our own interface, an adapter under `Core/Providers/`, `BackendUnavailableException` for "can't reach it", `BackendProbe` to tell a dropped request from a crash, and a health check tagged `BackendHealth.Tag` so it shows on the Status page. Book lookup (Open Library, over the internet) follows the same pattern, with `IBookCatalog` and `BookLookup:Provider`.

Most podcasts publish no transcript, so most episodes go through speech-to-text.

## Layout

| Project | Contents |
|---|---|
| `src/PodcastBookRecs.Core` | EF Core model and migrations (`Data/`), feed parsing (`Feeds/`), transcript parsing (`Transcripts/`), pipeline services (`Pipeline/`), user admin (`Accounts/`), shared config, logging and Identity settings (`Configuration/`), backend contracts (`Backends/`), the transcription and extraction interfaces (`Transcription/`, `Extraction/`, which also holds the versioned prompts and the windowing, quote-matching and merging helpers), the book catalogue interface and matching rules (`BookLookup/`), ranking (`Books/`) and their adapters (`Providers/`), ffmpeg chunking (`Audio/`), the private-address guard (`Net/`) |
| `src/PodcastBookRecs.Worker` | Hosts the pipeline: `DatabaseMigrator` runs first, then `PipelineService` runs its loops (UI commands every 5 s, due feed polls every minute, transcript fetching, heartbeat, and transcription, extraction and book matching when their providers are set; without extraction, `PriorityRelease`). `BackendStatusPublisher` writes backend health rows every 30 s. |
| `src/PodcastBookRecs.Web` | Blazor Server UI |
| `tests/PodcastBookRecs.Tests` | Unit and integration tests |

The UI and the Worker never call each other. They share only the SQLite database: the UI writes `WorkerCommands` rows that the Worker polls, and the Worker writes `WorkerStatus` heartbeats that the UI reads.

## Pipeline rules

- **Episode states.** `New` (has a usable transcript link) → `TranscriptFetched`, or `AwaitingTranscription` (no usable link) → `Transcribing` (claimed by `EpisodeTranscriber`) → `Transcribed`. Either way, an episode with a transcript then goes `Extracting` (claimed by `EpisodeExtractor`) → `Extracted`. `Skipped` marks episodes outside the backfill window on a feed's first poll; they are stored so later polls don't treat them as new. `Failed` is used when transcription runs out of attempts, `ExtractionFailed` when extraction does (the transcript is kept). Enum values are stored: never renumber them.
- **Identity.** Episodes are deduplicated per feed on the item GUID, falling back to the enclosure URL.
- **Queue order.** The transcript fetcher, transcriber and extractor each take an in-progress episode first, then episodes with `PrioritisedAt` set (oldest request first), then newest by `PublishedAt`. "Do this next" (`PrioritiseEpisode`) sets `PrioritisedAt` and clears `NextAttemptAt`, only in `CommandProcessor.QueuedStates`; a prioritised episode skips the published-transcript grace period. `PrioritisedAt` clears on `Extracted`, `ExtractionFailed`, `Failed` and "Reset and retry". With extraction off, nothing would reach those, so the Worker runs `PriorityRelease` every 30 s instead, which clears it on `PriorityRelease.FinishedWithoutExtraction` under the lock (and catches episodes prioritised before extraction was turned off). `IncludeEpisode` moves a `Skipped` episode to `New` or `AwaitingTranscription` and then polls its feed, because skipped episodes' links were never refreshed; `PrioritiseEpisode` on a skipped episode includes it too.
- **Late transcripts.** Every poll refreshes the transcript links of episodes in `EpisodeIntake.RefreshableStates` and requeues an `AwaitingTranscription` episode only when its set of link URLs changed. `Transcribing` and `Extracting` must stay out of `RefreshableStates`, or a poll could requeue an episode mid-job. Feeds that have ever carried transcript links get `PodcastFeed.PublishesTranscripts`, and their new episodes wait `Transcription:PublishedTranscriptGraceDays` before transcription.
- **Episode state changes go through `EpisodeStateLock`.** The poller's refresh, the transcriber's and extractor's claims and completions, "Reset and retry", "Re-run book extraction", "Do this next" and "Include" all hold it, and the claim is a conditional `ExecuteUpdate`. Any new code that changes an episode's state in the Worker must take the same lock.
- **Transcription.** `EpisodeTranscriber` downloads audio, splits it with ffmpeg into WAV chunks, and saves each finished chunk as `chunk_NNN.json` in `/data/work/<episode>/`, so it resumes after a restart. The poller refreshes `EnclosureUrl` for waiting and transcribing episodes, because signed links expire.
- **Retries.** Transient HTTP errors back off exponentially up to `Polling:MaxAttempts`; a dead or unparseable link moves on to the next link, then to `AwaitingTranscription`. For transcription, `BackendUnavailableException` (connection refused, DNS, connect timeout, HTTP 502/503/504) and low disk pause without counting an attempt; everything about the episode itself (download errors, ffmpeg errors, rejected or timed-out chunks) counts one. Extraction uses the same rules: unreachable backend, HTTP 404 (model missing) and 502/503/504 pause; timeouts, other errors and unparseable answers count.
- **Extraction.** `EpisodeExtractor` splits the transcript into overlapping word windows (`TranscriptWindows`; words, not time, because plain-text transcripts have no timings), sends each to `IBookExtractor`, keeps only mentions whose quote `QuoteLocator` finds in that window (exact, then at least 80% of words), and merges repeats per title (`MentionMerger`). Stored quotes and timestamps come from the transcript, never the model. No checkpointing: an episode takes minutes, so a restart redoes it. Completion re-checks the state and the transcript ID under the lock and discards results if either changed. `ReextractEpisode` only accepts `Extracted` or `ExtractionFailed`.
- **Prompts are versioned files** (`Extraction/Prompts/book-mentions-vN.txt`, embedded). Never edit a released prompt: add the next version and bump `ExtractionPrompt.Version`, which is stored on every mention. The transcript goes inside `<transcript>` tags and the prompt says it is data; `ExtractionPrompt.UserMessage` defuses any such tag in the text.
- **Book matching.** `MentionMatcher` takes the oldest mention whose `MatcherVersion` isn't `CatalogMatcher.Version` (so new mentions, and all of them after a rules change). It also takes a `NoMatch` again after `MentionMatcher.RetryNoMatchAfter` (30 days), behind new mentions like a due `LookupFailed`; the queue and `SaveAsync`'s guard share `IsDue`, so a retried mention can't be picked and then have its answer dropped. It reuses the answer of any mention with the same `LookupKey` already matched, or not found within those 30 days, under the current version; otherwise it searches the `BookCatalogChain` (`BookLookup:Provider`, then each of `BookLookup:Fallbacks`): each catalogue with the author, then the title alone, and `CatalogMatcher.Pick` decides. Fallbacks are asked only after the primary picks nothing and only when the author has a surname (`CatalogMatcher.HasSurname`), since they have no edition counts (`EditionCount` null never passes the no-author rule or sets `FewEditions`); a fallback match gets `MatchDoubts.OtherCatalogue`, so it always goes to review. A fallback that fails (`BackendUnavailableException` or `CatalogLookupFailedException` from a catalogue after the primary) is skipped and the next one asked, so one fallback being down or its token expiring neither pauses matching nor hides the later fallbacks. If none matches, the mention is `LookupFailed` when some fallback was unreachable (it might have had the book) and `NoMatch` when every failure was a `CatalogLookupFailedException` (rejected token, bad answer), so a dead token costs no daily retries. The log warns once per failing fallback, not per title. For the primary, unreachable, 429 and 5xx pause; any other bad answer marks that mention `LookupFailed` so it can't block the queue, and it is tried again after `MentionMatcher.RetryFailedAfter` (a day). Only a `Matched` answer that still has its `BookId` is reused. The "book lookup" Status row (`BackendHealth.BookLookup`) exists only while lookup is configured; the UI uses it to say lookup is off instead of "checking". The "extraction" row (`BackendHealth.Extraction`) works the same way: with it missing, the episode page shows "Find books" as off, says the transcript won't be searched, and hides "Do this next" on episodes that have their transcript. Mentions aren't episode state, so matching takes no `EpisodeStateLock`: updates are conditional on the version, and a mention deleted mid-lookup updates nothing. Only this loop adds `Book` rows.
- **Review decisions.** A `ReviewDecision` is a person's ruling on one `LookupKey` (Confirmed, Corrected with a `Pick`, NotABook, WrongBook, KeptAsIs with a `Manual` `Pick`) and applies to every mention with that key. The Web writes the row, together with a `ReviewDecided` command in the same `SaveChanges`; the command only clears `MatcherVersion` on mentions with that key. Only `MentionMatcher` turns a decision into match state, reading it before reuse or search, and only it adds the picked `Book`. Its saves are guarded inside the `ExecuteUpdate`: an answer from the catalogue or reuse is dropped if a decision now exists for the key, and an answer from a decision is dropped if that decision's `Id` and `DecidedAt` changed. Either way the mention stays due. `MatchState.Rejected` comes only from a decision and has no book. A decision that can't be applied marks the mention `LookupFailed`, so it can't loop.
- **Keep as is.** `ReviewActions.KeepAsIsAsync` builds the pick itself: `Provider = BookLookupProviders.Manual`, `CatalogId` the decision's `Id` (`N` format), no links, the typed title and author with control characters made spaces. The decision's `Title` and `Author` still record the mention's text, because re-keying depends on them. The matcher applies a `Manual` pick only for `KeptAsIs` and only when its ID is that decision's; `CorrectAsync` and the matcher's `Corrected` path refuse one, and the matcher and review search both store answers under the catalogue they asked, whatever `Provider` the entry carried. Re-deciding a key reuses its decision row, so keeping it again with new text refreshes the same `Manual` book; undo and keep makes a new book and leaves the old one without mentions. `Manual` isn't in `BookLookupProviders.Known`, so config can't choose it.
- **A `CatalogBook` records its catalogue** in `Provider`. Picks and search results stored before that have none and count as Open Library (`ProviderOrDefault`); `CatalogMatcher.IsUsable` accepts only a known provider whose `InfoUrl` is on `BookLookupProviders.InfoHost` and whose cover, if any, is on `CoverHost` (both through `IsSafeLink`), or a `Manual` entry with a GUID ID and no links.
- **The review page.** `ReviewBacklog` lists keys with no decision whose mentions, matched under the current version, include a `NoMatch` or `LookupFailed`, a match with `Doubts`, or a highest `Confidence` below `ReviewBacklog.LowConfidence`; `CountAsync` is one grouped SQL query for the nav badge. All page writes go through `ReviewActions`, which only accepts a key some mention has (and records that mention's title and author), trims and caps text, takes a confirmed `BookId` from the mentions and copies a pick from a stored `CatalogSearch` result (checked with `CatalogMatcher.IsUsable`), never from the page.
- **Catalogue searches run in the Worker.** The Web inserts a `CatalogSearch` row and polls it; `CatalogSearchRunner` answers on its own 1 s loop (not a command: the command loop can be busy for minutes) through the same `BookCatalogChain` as the matcher, so each adapter's pacing covers both. It asks every catalogue at once (`Task.WhenAll`, results kept in chain order) within `SearchTimeout` of the search's `CreatedAt` (25 s, under the page's 30 s wait, so a search queued behind another gets only what's left, and one with none left gets `ExpiredError`), keeps up to `MaxResultsPerCatalogue` from each, stamps each result's `Provider` with the catalogue that answered, and fails only when every catalogue does; when some answered and some didn't, it stores the results with `PartialError`, and the page shows both. Never call `IBookCatalog` from the Web. At most `ReviewActions.MaxOpenSearches` wait at once; a search failure stores a fixed message, never the catalogue's text.
- **Command results reach the UI.** A refusal throws `CommandRefusedException` with a message written for the person; anything else stores `CommandProcessor.FailedError`, because exception text can carry paths or feed tokens. Pages send commands through `CommandFeedback`, which shows a refusal in a snackbar.
- **Lookup keys are stored data.** Decisions are keyed on `CatalogMatcher.LookupKey`, built from `MentionMerger.TitleKey` and the surname rule. Changing either orphans every decision without an error, so it needs a step that re-keys `ReviewDecisions` from their `Title` and `Author`. `Lookup_keys_stay_the_same` pins the current keys.
- **Plain-text transcripts** get speakers from `Name:` paragraph prefixes when at least half the paragraphs have one (`TranscriptParser`).

## Data model conventions

- **Keys are version 7 GUIDs**, created in code (`= Guid.CreateVersion7()`), not by the database. They sort by creation time. `WorkerStatus` is the exception: its key is the component name (e.g. `worker`). Don't order by GUID when exact order matters; `CommandProcessor` orders by `CreatedAt`.
- **All `DateTime`s are UTC.** `AppDbContext.ConfigureConventions` marks every `DateTime` read from SQLite as UTC. Convert to local time only for display (`Display.LocalTime`). Don't switch to `DateTimeOffset`: the SQLite provider can't translate its comparisons or ordering to SQL.
- **Mentions belong to their transcript.** `BookMention` has cascade-delete foreign keys to both `Episode` and `Transcript`, so "Reset and retry" or a new transcript removes stale mentions. Books outlive their mentions (`BookMention.BookId` is set null if a book is ever deleted; nothing deletes books). Title, author and quote are length-capped (`BookMention.Max*Length`) before storing, since they come from the model.
- **JSON columns** hold `Episode.TranscriptLinks` and `Transcript.Segments` through value converters. A transcript lives in its own table, one per episode.
- **Names stay provider-neutral.** Stored values and enum names never name a vendor (`TranscriptSource.Transcribed`, not `Whisper`). Record which provider and model produced data in their own columns (`Transcript.Provider`, `Transcript.Model`, and on `BookMention` also `PromptVersion` and `MatcherVersion`; `Book.Provider` with `Book.CatalogId`).
- **Decisions belong to no mention.** `ReviewDecision` has no foreign key to mentions, episodes or transcripts, so deleting those never deletes a decision. Its `BookId` is set null if a book is ever deleted.

## Migrations

- Only the Worker applies migrations, at startup. The UI's `SchemaGate` waits until none are pending and never creates the database file.
- **The app is deployed, so never regenerate or edit an existing migration.** Add a new one: `dotnet tool restore`, then `dotnet ef migrations add <Name> -p src/PodcastBookRecs.Core -s src/PodcastBookRecs.Core -o Data/Migrations`. Check with `dotnet ef migrations has-pending-model-changes` (same `-p`/`-s`).
- Migrations are marked as generated code in `.editorconfig`, so analysers skip them.

## SQLite on a shared volume

Both containers open one SQLite file in WAL mode with a 30 s busy timeout (`SqlitePragmaInterceptor`). Keep write transactions short. `/data` must be on local disk, never an SMB/NFS share.

## Security and privacy

- **Private feed URLs carry subscriber tokens** in the path or query (Supporting Cast, Patreon). Never log or display one: use `FeedUrlRedactor.Redact` (host only). `System.Net.Http.HttpClient` logging is held at Warning because it logs full request URLs. Episode enclosure URLs from private feeds carry the token too, so the UI never shows them.
- **Feed content is untrusted.** XML is parsed with DTDs ignored and no resolver. Feed and transcript downloads are capped on bytes actually read (`LoadIntoBufferAsync(max)`), not only on `Content-Length`; audio is capped while streaming. Only http(s) feed URLs are accepted (`FeedUrl.IsValid`).
- **Private-address guard.** The `feeds` and `enclosures` HTTP clients connect through `OutboundConnections.ConnectToPublicAddressAsync`: it resolves once, refuses any non-public address (`PrivateAddressGuard`), connects to the vetted IP, and needs `UseProxy = false`. Any new client for feed-supplied URLs must use `ServiceCollectionExtensions.CreateFeedHandler`. User-configured backends (the transcription client) are exempt. `Http:AllowPrivateNetworkFeeds` turns the guard off.
- **ffmpeg runs on untrusted files** with `-protocol_whitelist file` and `-format_whitelist` (no playlists or concat, which would let a file make ffmpeg open other inputs), a duration cap, a wall-clock timeout, `ArgumentList` arguments and bounded stderr. Keep all of these if you change the command. ffmpeg's stderr goes to logs, never to `LastError`.
- **Catalogue data is untrusted.** Adapters send through `CatalogHttp` (1 MB cap while reading, 429 and 5xx pause, other statuses fail the title, no URL in messages), on handlers that follow no redirects, and pace their requests with a `CatalogPacer`. An adapter whose catalogue says "slow down" with another status passes it as `alsoUnavailable`, to the health check too: only Apple does, for 403. Never widen the shared default, or a rejected token from another catalogue would pause matching. Adapters are keyed singletons by provider name, each with a health check (`CatalogHealthCheck`, or `HardcoverHealthCheck` for Hardcover); `BackendHealth.BookLookup` is always the primary's row and fallbacks get `BookLookupFallback`. `CatalogMatcher.IsUsable` also checks a pick's link and cover with `CatalogMatcher.IsSafeLink` (https, parsed host exact or dot-suffixed, default port, no user info) against `BookLookupProviders.InfoHost` and `CoverHost`. The Apple Books adapter keeps only numeric `trackId`s, builds `https://books.apple.com/<country>/book/id<trackId>` itself, keeps a cover only through `CatalogMatcher.SafeLinkOrNull` for `mzstatic.com` (which checks the escaped form that gets stored), keeps a name suffix ("King, Jr.") with its author, and takes `AppleBooks:Country` only as two lower-case letters. The Hardcover adapter posts a fixed GraphQL query with the term only in `variables` (built with `JsonObject`), sends the token as `Authorization: Bearer` to a fixed `https://api.hardcover.app` whose client redacts that header from logs, lets 401 and 403 fail the request (the matcher then skips Hardcover for that title), turns a GraphQL `errors` answer into `CatalogLookupFailedException` carrying at most a short `extensions.code` (the message can echo the title), keeps only numeric IDs and `^[a-z0-9-]{1,200}$` slugs, builds `https://hardcover.app/books/<slug>` itself and keeps covers only through `SafeLinkOrNull` for `assets.hardcover.app`. `Hardcover:Token` is required only when Hardcover is in the chain, comes from `PBR_Hardcover__Token`, and is never logged or put in a message. `HardcoverHealthCheck` (not `CatalogHealthCheck`, whose GET can't test a token) posts a one-result search, parses a 2xx answer with the adapter's own `Parse` (a GraphQL error arrives as HTTP 200), and reuses the result for 30 minutes, or 5 for 429 and 5xx, because every request counts against the daily limit. The Open Library adapter follows no redirects, keeps only work keys matching `^/works/OL\d+W$`, and builds `Book.InfoUrl` and `Book.CoverUrl` itself from checked IDs. The UI still renders them only through `Display.HttpsOrNull`. `Book.InfoUrl` is null for a `Manual` book, so every consumer must handle null. `OpenLibrary:ContactEmail` goes into the User-Agent, so `OpenLibraryOptions` accepts only a plain address, and it is never logged.
- **LLM output is untrusted.** Render titles, authors and quotes as plain text (no `MarkupString`). The adapter caps an answer at 2,048 tokens, 50 mentions per window and 1 MB of response.
- Don't render feed-supplied URLs as `href`s without checking the scheme is http(s).
- **Login.** ASP.NET Core Identity, users only (`IdentityUserContext<AppUser, Guid>`, no roles). A fallback policy requires a signed-in user on every endpoint, the Blazor hub included. Only static assets, `/health`, `/account/login`, `/account/login-2fa` and `/Error` are anonymous; anything new that must be reachable signed out needs `[AllowAnonymous]` or `.AllowAnonymous()`. Every page also carries `[Authorize]` from `_Imports.razor`, because `AuthorizeRouteView` checks attributes, not the fallback policy. Lockout (5 attempts, 15 minutes) and the 12-character, length-only password rule live in `IdentityExtensions`, which the tests share. Two-factor sign-in uses an authenticator app (TOTP) only, enrolled with `users 2fa-enable`; `/account/login-2fa` is the second step. Only the authenticator token provider is registered: nothing sends reset or confirmation tokens.
- **Sessions end on a password reset.** The cookie and open circuits both re-check the security stamp every 5 minutes (`IdentityRevalidatingAuthenticationStateProvider`). A circuit that fails the check renders `RedirectToLogin`.
- **Behind cloudflared the app sees plain HTTP.** `UseForwardedHeaders` runs first and trusts `X-Forwarded-Proto`/`For` from `ForwardedHeaders:KnownNetworks` (private ranges by default), so the cookie gets the Secure flag and redirects use https. It deliberately ignores `X-Forwarded-Host`.
- **No sign-up page.** Accounts come from `entrypoint.sh users add|reset-password|2fa-enable|2fa-disable <email>` (`UserCommands`, backed by `UserAdmin`). Don't add self-registration or a first-run setup page: on an exposed host, whoever reaches it first owns the app.
- Identity's `LockoutEnd` is a `DateTimeOffset`. That is the one exception to the UTC `DateTime` rule; Identity compares it in memory, never in SQL.

## Build and tooling

- `TreatWarningsAsErrors` with `AnalysisLevel` latest-recommended. Use `[LoggerMessage]` source-generated logging, and compute log arguments before the call (CA1873).
- Test names use underscores (CA1707 is off for `tests/` only). Pass `TestContext.Current.CancellationToken` to async calls (xUnit1051).
- The ffmpeg tests run the real binary: skipped locally without ffmpeg, failing on CI (`CI=true`), which installs it in the "Build and test" job.
- `HttpClient` throws the same `TaskCanceledException` for a connect timeout and a request timeout. The transcription client does its own connecting (`OutboundConnections.ConnectWithTimeout`) so "can't connect" always surfaces as `HttpRequestError.ConnectionError`.
- Fixtures are short invented files under `tests/PodcastBookRecs.Tests/Fixtures/`, never real transcripts or feeds. Integration tests run against a migrated temp SQLite file with a stub `HttpMessageHandler`.
- `global.json` pins SDK 10.0.402 with `rollForward: feature`. Keep it that way: `actions/setup-dotnet` turns `latestFeature` or `latestPatch` into "newest available", which once pulled an unreleased SDK and broke CI. Bump the version deliberately.
- To try production code against real data without committing it, use a .NET 10 file-based app in a scratch folder (`#:project` pointing at Core, plus `#:property PublishAot=false` if it uses reflection-based JSON).

## Docker image

One image runs either app: `entrypoint.sh worker|web`. Things that broke before and are handled in the Dockerfile:

- `.editorconfig` must be copied into the build, or analyser rules switched off for migrations come back on.
- Publish must restore again after the source is copied: the SDK only adds the package that ships `blazor.web.js` once it sees `.razor` files.
- `entrypoint.sh` changes into each app's folder, because ASP.NET Core uses the working directory as its content root.
- The image publishes for one runtime (from `TARGETARCH`) and runs as UID 1654, which must own the `/data` bind mount. Data Protection keys live in `/data/keys`; transcription scratch files in `/data/work`.
- ffmpeg comes from Ubuntu's apt package (6.1 at the time of writing). It roughly doubles the image size; a static build would be smaller but adds a third-party supply-chain dependency.

CI pushes `ghcr.io/thelaw51/podcastbookrecs` tagged `latest` and `sha-<short>` from `main`, plus semver tags from `v*` tags. The "Docker image" job builds alongside the tests and pushes by digest only; "Publish image" applies the tags once both pass, so a tag never points at an untested build. Its tag rules repeat the image job's `metadata-action` step: change both together. The package is public. Deployment is a manual re-pull in Portainer; no auto-deploy.

## UI

- MudBlazor components, `Typo.*` and `Color.*`, no hard-coded colours. Every page has loading, empty and error states. Load data in `OnInitializedAsync` or `OnParametersSetAsync`.
- **Pages never show exception text.** A failed load or action logs the exception with `UiLog.ActionFailed` and shows a fixed message ("Couldn't load ... The web app's log has the details."), because exception text can carry file paths, SQL or connection details. Only messages written for the person (`ReviewActionException`, `CommandRefusedException`) reach the page as they are.
- Prerendering is off (`App.razor`) so pages load data once and `SchemaGate` can wait without blocking the first response.
- **Account pages render statically.** `/account/login`, `/account/logout` and `/Error` carry `[ExcludeFromInteractiveRouting]` and use `AccountLayout`, because only an HTTP response can set or clear the auth cookie. MudBlazor inputs need a circuit, so the sign-in form uses `EditForm` with plain inputs styled in `app.css`. That is the deliberate exception to the MudBlazor rule. Static pages must never sit inside `SchemaGate`: its polling loop would hold the response open.
- **Books page filters live in the query string.** `BookListParameters` parses it (ignoring anything malformed, capping text and podcast count) and builds `BookFilter` with local days turned into UTC bounds. `BookListQuery` applies podcast and date filters in SQL before ranking and the text and recommended filters after, without renumbering; exports must reuse it so they match the page. A filter change navigates (`replace: true`) and `OnParametersSetAsync` reloads; the layout keys pages on the path, so the page isn't remounted. MudBlazor inputs echo a changed parameter object back through their `...Changed` callback, so pass them the same instance unless the value changed, and `Apply` skips navigating to the URL already shown.
- **Exports** (`BookExportEndpoints`, minimal API GETs under `/books/export…`) parse the page's query string with `BookListParameters` and load through `BookListQuery`, plus `LoadMentionsAsync` for the mentions that counted, so a file matches the page. They check `SchemaStatus` first (503 until the Worker has made the database) and send `Cache-Control: no-store`. `BookExport.Cell` quotes every CSV cell and prefixes `'` to a leading `= + - @`, tab or CR. The Goodreads file keeps Goodreads' export column names and has no byte order mark. The page links to them with a `download` attribute, which keeps Blazor's router from handling the link.
- **Transcript links carry a time, not a row** (`TranscriptLinks`): `episodes/{id}#at-754.601`, rounded up to the millisecond so it can't land on the previous row, or `#mentions` without a time. The episode page maps the time to row `t-{index}` after its data renders and scrolls with `EpisodeDetail.razor.js`; its own timestamps call that directly, because a link to the URL already showing raises no navigation.
- User-facing text says "podcast"; the entity is `PodcastFeed`. Routes take GUIDs: `/podcasts/{Id:guid}`, `/episodes/{Id:guid}`.
- UI actions never touch the pipeline directly: they insert a `WorkerCommand`.

## Third-party services must be swappable

This is a standing requirement for all work on this project. Every external service is used through our own interface, so moving to a different provider means writing one new adapter and changing config, not editing the pipeline or the UI.

That covers today's and planned services: Whisper (transcription), LM Studio (book extraction), Open Library (book lookup), Audiobookshelf (local audio files), and anything added later. Feed polling is exempt because RSS and Podcasting 2.0 are open standards, not providers.

### Rules

- **Interface first.** Core defines an interface named for the job, not the vendor: `ITranscriptionService`, not `IWhisperClient`. Pipeline services depend only on that interface.
- **One adapter per provider.** Each implementation lives in its own folder, e.g. `Core/Providers/Transcription/OpenAiCompatible/`. Nothing outside that folder references the provider's types, SDK or wire format.
- **Our types at the boundary.** Adapters return the project's own records (such as `TranscriptSegment`), never provider DTOs. Provider-specific errors become our own exceptions, e.g. one meaning "backend unavailable" that the pipeline handles the same way for every provider.
- **Chosen by config.** A `Provider` key in each service's config section picks the implementation, alongside its base URL, model name and credentials. Switching provider must not need a code change or a new image.
- **Prefer standard protocols over vendor SDKs.** An OpenAI-compatible endpoint lets one adapter serve whisper.cpp, MLX servers, LM Studio, Ollama and hosted APIs alike. Only add a vendor SDK when no standard protocol does the job, and keep it inside the adapter.
- **Record provenance.** Store which provider and model produced each piece of derived data (transcripts, mentions, book matches), so results from different backends can be told apart and re-run selectively.
- **Same status contract.** Every external backend reports reachability through one shared interface, which the Status page shows. Adding a provider adds a row without changing the UI.
- **Tests against the interface.** Pipeline tests use fakes of the interface, never a real provider. Each adapter gets its own tests, using small recorded response fixtures.
- **Document the switch.** The README says how to point each service at a different provider.

When a change touches a third-party service, check it against these rules before calling it done.

## Branch protection and CI job names

`main` is protected by the "Protect main" ruleset: no direct pushes, force pushes or deletion, and every change goes through a pull request. A PR can only merge when the required checks named "Build and test" and "Docker image" pass.

Those names are the `name:` of the two jobs in `.github/workflows/ci.yml`, and the ruleset matches them exactly. If you rename either job, or split or replace it, update the ruleset's required checks in the same change (Settings → Rules → Rulesets → Protect main). Otherwise every PR waits forever for a check that never reports.
